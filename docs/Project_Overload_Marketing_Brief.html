01 — Overview
What is Project Overload?

Project Overload is a conversational AI platform that lets anyone — from executives to analysts — define, run, and automate business intelligence reports using plain English. No SQL skills needed. No dashboard configuration. Just talk to it.

"Define once, run forever. Report contracts lock your business logic and execute on your schedule."

The Problem We Solve

⚠
The BI Gap
Business users need analytics but lack SQL skills. Existing BI tools require complex manual setup, query writing, and ongoing maintenance by technical teams.
⏰
Report Fatigue
Recurring reports are rebuilt manually every cycle. Inconsistent formatting, missed deadlines, and lost institutional knowledge make reporting a drag.
🔍
Insight Blindness
Raw data gets delivered without context. Reports show numbers but miss the "so what" — the trends, drivers, and recommended actions that drive decisions.
🔒
Governance Gaps
Ad-hoc queries bypass security controls. No audit trail, no table restrictions, no guarantee that the same report produces the same logic twice.

💬
1. Conversational Scoping
Users describe what they need in plain English. The AI asks clarifying questions over 5–15 turns to nail down: report name, audience, metrics, filters, schedule, and timezone. A scope confirmation step ensures alignment before any queries run.
🧠
2. Query Strategy
The Query Strategist AI generates 2–4 targeted SQL queries from the conversation context and database catalog. Each query is validated against table allowlists and security guardrails before execution.
🔎
3. Per-Question Analysis
Each query result is analyzed independently by the AI Analyst, which identifies trends, anomalies, and insights. A 90% confidence threshold ensures only high-quality findings make it into the final report.
📄
4. Report Composition
All analyses are synthesized into a rich HTML report structured as an executive brief: What Changed, Why (drivers), So What (implications), What To Do (actions), plus an evidence appendix.

Evidence-Based, Not Hallucinated

Every finding in a report is backed by actual query results (up to 200 evidence rows). Query hashes and freshness metadata ensure full reproducibility and audit trail. The system never guesses — it shows its work.

The newest addition to Project Overload — define a report once in conversation, then let the system run it automatically on a recurring schedule.

New Feature

Set It and Forget It

After building a report through chat, users can lock it into a schedule profile. The system handles everything: rolling reporting windows forward, re-executing queries, running AI analysis, composing the report, and generating the PDF — all automatically.

Describe your industry, use case, and domain — so the AI understands your data semantically.
Activate & Query
Connection goes live. Multiple databases can be active simultaneously in a single session.

Security Guardrails

🛡
Read-Only Enforcement
No INSERT, UPDATE, DELETE, or DDL operations — ever. The SQL Guard package validates every query before execution.
📋
Table Allowlisting
Admins define exactly which tables are queryable. The AI cannot access, reference, or even see non-allowlisted tables.
📐
Row Caps & Limits
Evidence tables are capped at 200 rows per query. Prevents runaway queries, controls cost, and keeps analysis focused.
📝
Full Audit Trail
Every contract, run, query, and approval is logged. Complete traceability from conversation to report delivery.

07 — User Journey
From Zero to Automated Report

A typical user's journey from first login to receiving automated weekly reports.

Step 1: Connect a Database
Navigate to the Connect page. Paste your PostgreSQL or Snowflake connection string. Test and activate in under a minute. Set your table allowlist and business context.
Step 2: Start a Conversation
Open Chat Explorer. Type something like: "I need a weekly CEO dashboard showing revenue trends, top customers, and churn risk." The AI begins asking clarifying questions.
Step 3: Refine Through Dialogue
Over 5–15 messages, narrow down: audience (CEO + board), metrics (MRR, net revenue retention, churn %), time range (trailing 4 weeks), and filters (exclude test accounts). Toggle insight mode as needed.
Step 4: Review Scope Confirmation
The AI presents a structured scope summary for your approval. Review the planned queries, target tables, and analysis approach before committing.
Step 5: Generate First Report
The pipeline runs: Query Strategist plans 2–4 SQL queries, DataPlane executes against your live database, Analyst evaluates each result, Report Composer synthesizes into a structured executive brief.
Step 6: Download or Schedule
View the rich HTML report in-app. Download as PDF. Or lock it into a schedule: "Run every Friday at 6pm IST." The system auto-generates a schedule draft with per-question rerun configurations.
Step 7: Sit Back and Receive
Reports run automatically on schedule. View run history on the Scheduled Reports dashboard. Open any past run in chat to ask follow-up questions or compare with previous periods.

Time to First Report: Minutes, Not Weeks

Traditional BI setup takes weeks of requirements gathering, dashboard building, and iteration. With Project Overload, users go from zero to their first automated report in a single conversation — typically under 15 minutes.

11 — Marketing Checklist
Content & Branding Guidelines

Essential checklist for the marketing team when creating content, campaigns, and brand assets for Project Overload v2.

Brand Positioning & Messaging

  • Lead with the outcome, not the technology. Users don't care about "multi-LLM pipelines" — they care about getting executive reports in 15 minutes instead of 2 weeks. Always lead with business value.
  • Use the "Define Once, Run Forever" tagline. This is the core differentiator. Report Contracts are the hero concept — emphasize the shift from manual, repetitive reporting to automated delivery.
  • "Zero SQL Required" is a primary hook. Emphasize the conversational interface. Show before/after: SQL query vs. plain English question producing the same report.
  • Position as "AI Analyst, Not AI Dashboard." We don't just show charts — we analyze, explain why, and recommend what to do. The executive brief format (What/Why/So What/Actions) is the differentiator.
  • Emphasize trust and governance. In the AI era, trust matters. Lead with: evidence-based (no hallucination), read-only access, table allowlists, audit trail, 90% confidence threshold. These are enterprise selling points.

Content Strategy

  • Create persona-specific landing pages. Build separate messaging for: (1) Executives who want automated reports, (2) Analysts who want to escape report drudgery, (3) Data engineers who want governed self-serve, (4) Department heads who want independence from IT.
  • Showcase the Scheduled Reports feature prominently. This is the newest and most differentiating capability. Create a dedicated feature page, demo video, and announcement blog post. Highlight the "set it and forget it" angle.
  • Build a "Time to First Report" narrative. Create content showing the journey: connect database → have a conversation → get a report → schedule it. Emphasize the speed (minutes, not weeks). Video walkthroughs are ideal.
  • Develop comparison content vs. traditional BI tools. Use the differentiators table in this document. Create blog posts, infographics, and social content around: "Tableau vs. Project Overload" or "Why your dashboards aren't enough."
  • Produce use case templates. Create ready-made report templates for common scenarios: CEO Weekly Dashboard, Monthly Revenue Report, Quarterly Business Review, Customer Churn Analysis, Marketing ROI Tracker, Sales Pipeline Health.

11 — Marketing Checklist (Continued)
Content & Branding Guidelines

Visual Identity & Design

  • Use the dark, premium aesthetic. The product has a dark UI with purple/violet accents. Marketing materials should mirror this: dark backgrounds (#0F0B1A), purple gradients (#6C3AED to #EC4899), and clean typography.
  • Show the conversation, not the dashboard. Hero images should feature the chat interface, not traditional BI charts. The conversation IS the product — make it the visual centerpiece.
  • Visualize the pipeline. The 6-stage pipeline (Chat → Strategy → Execute → Analyze → Compose → PDF) is visually compelling. Use it in diagrams, animations, and explainer content.
  • Create before/after comparisons. Side-by-side visuals: messy spreadsheet vs. polished executive PDF. Raw SQL vs. natural language question. Manual weekly rebuild vs. automated delivery notification.
  • Design social-ready report snippets. Take real (anonymized) report sections and turn them into shareable graphics. The executive brief format is visually distinctive — use it.

Messaging Pitfalls to Avoid

  • Don't call it a "chatbot." It's an AI-powered business intelligence platform. "Chatbot" undersells the analytical depth. Use: "conversational analytics," "AI analyst," or "report automation platform."
  • Don't over-promise on AI accuracy. We have guardrails (90% confidence filter, evidence-based analysis), but never claim "100% accurate." Messaging should emphasize: "evidence-backed," "auditable," "transparent reasoning."
  • Don't ignore the human-in-the-loop. The scope confirmation step and approval workflow are features, not limitations. Emphasize: "You stay in control. The AI proposes, you approve."
  • Don't hide the LLM dependency. Be transparent that reports are AI-generated via Claude. In 2026, AI transparency is a trust signal, not a weakness. Mention the model by name.
  • Don't position as a replacement for data teams. Position as a force multiplier: "Give your data team superpowers" not "Fire your data team." Enable self-serve for stakeholders while freeing analysts for higher-value work.
  • Don't lead with database count. "Supports 6 databases" is a checkbox feature. Instead, lead with: "Connects to the database you already use" — make it feel effortless, not spec-sheet.
